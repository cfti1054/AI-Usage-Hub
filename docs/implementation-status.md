# 구현 범위 (2026-10-12 기준)

AI Usage Hub에 지금까지 구현된 기능과 아직 구현되지 않은 기능을 정리했습니다. 설계 근거와 결정 이유는 [initial-development.md](initial-development.md), DB 구조는 [erd.md](erd.md), 화면 사용법은 [user-guide.md](user-guide.md)를 참고하세요.

## 1. 구현 완료

### 1.1 백엔드 (FastAPI, `backend/`)

| 기능 | 내용 | 주요 파일 |
|---|---|---|
| 로그인 | 이메일·비밀번호 로그인 → JWT 발급. 비밀번호는 scrypt 해시 | `app/routers/auth.py`, `app/security.py` |
| 서비스 관리 | 목록·추가·수정·활성화/비활성화. 기본 서비스 4종(Claude Code, Codex, Cursor, Gemini CLI) 자동 생성 | `app/routers/services.py`, `app/seed.py` |
| 서비스 API 키 | 저장(Fernet 암호화)·삭제·연결 테스트. 응답에는 끝 4자리만 노출 | `app/credentials.py` |
| 구독 관리 | 요금제·가격·통화·결제 주기·갱신일 등록, 수정, 삭제 | `app/routers/subscriptions.py` |
| 수동 입력 | 사용량(지표·사용값·한도·단위)과 월 비용 입력. `source_type`으로 수동/CLI 구분 | `app/routers/usage.py` |
| 대시보드 집계 | 요약 4칸, 서비스 카드 상태(정상·데이터 없음·수집 불가·실패·비활성·오래됨), 최근 7일 API 비용 | `app/routers/dashboard.py`, `app/reports.py` |
| 비용 분석 | 월별 구독료와 API 비용 분리, 원 통화 표시, 12개월 서비스별 추이 | `app/routers/costs.py` |
| 환율 | 자동 조회(6시간 주기, 실패 시 기존 값 유지)와 직접 입력 전환 | `app/fx.py`, `app/routers/settings.py` |
| 자동 수집 엔진 | 커넥터 실행 → 저장 → 수집 이력. 비용은 덮어쓰기(upsert), 오류 메시지의 API 키 마스킹 | `app/sync.py`, `app/connectors/` |
| 스케줄러 | 1시간 주기 수집(설정에서 15~1440분 변경), 6시간 주기 환율 갱신 | `app/scheduler.py` |
| DB 마이그레이션 | 0001 초기 스키마, 0002 환율 자동 조회 | `migrations/versions/` |
| ERD 자동 생성 | 모델에서 `docs/erd.md` 생성, 테스트가 최신 여부 검사 | `app/erd.py` |

API 목록은 [initial-development.md](initial-development.md)의 6장에 있습니다. 서버를 띄운 뒤 `/docs`에서도 확인할 수 있습니다.

### 1.2 프론트엔드 (Next.js 15, `frontend/`)

| 화면 | 경로 | 내용 |
|---|---|---|
| 로그인 | `/login` | 로그인 후 쿠키(httpOnly)에 토큰 저장 |
| 대시보드 | `/` | 요약 4칸, 서비스 카드, 비용 비중 도넛, 최근 7일 API 비용, 다음 자동 수집·환율 표시, 새로고침 |
| 서비스 상세 | `/services/{id}` | 최신 지표, 수동 입력 폼, 비용 기록, 수집 이력. 커넥터가 있으면 연결 테스트·즉시 수집 버튼 |
| 비용 분석 | `/costs` | 월 선택, 구독료/API 비용 분리, 환율 기준·출처, 12개월 추이 차트 |
| 설정 | `/settings` | 서비스 활성화·추가, API 키, 구독 정보, 환율, 표시·알림·수집 설정 |

백엔드 호출은 모두 Next.js 서버에서만 일어나므로 브라우저에 토큰이나 백엔드 주소가 노출되지 않습니다.

### 1.3 Claude Code 로컬 수집기 (`backend/collector/claude_code.py`)

- PC의 `~/.claude/projects` 세션 로그에서 토큰 사용량(입력·출력·캐시 생성·캐시 읽기)을 집계합니다.
- 같은 메시지가 여러 줄에 반복 기록되므로 메시지 ID 기준으로 한 번만 셉니다.
- 이번 달 누계를 서버에 올리고, 대시보드의 Claude Code 카드에 표시됩니다.
- `--dry-run`으로 서버 전송 없이 집계만 확인할 수 있습니다.
- Windows 작업 스케줄러에 등록해 정기 실행할 수 있습니다.

## 3. 알려진 제한 사항

- **자동 수집 대상 없음:** 커넥터가 아직 없어서 대시보드의 "새로고침"과 1시간 주기 수집은 실제로 가져오는 데이터가 없습니다. 지금은 수동 입력과 Claude Code 수집기만 데이터를 넣습니다.
- **구독 정보 자동 조회 불가:** Claude Pro/Max 같은 개인 구독의 요금제·결제 정보를 가져오는 공개 API가 없어 직접 등록해야 합니다.
- **모바일·웹 사용량:** PC 로그가 없으므로 자동 수집할 수 없고 수동 입력만 가능합니다.
- **여러 PC:** 각 PC가 이번 달 누계를 올리면 마지막에 올린 값만 보입니다(기기별 관리 기능으로 해결 예정).
- **캐시 토큰:** Claude Code 토큰 총합에는 캐시 읽기 토큰이 포함되어 실제 체감 사용량보다 크게 보일 수 있습니다.
- **한도 사용률:** 구독의 세션·주간 한도 사용률(%)은 로그에 없어 계산하지 않습니다.
- **백엔드 연결 실패 시 화면:** 백엔드에 연결할 수 없으면 프론트엔드가 안내 문구 대신 "Application error"를 보여 줍니다. 오류 안내 화면은 아직 없습니다.
- **스케줄러:** API 프로세스 안에서 실행되므로 Railway 레플리카를 1개로 유지해야 합니다.
